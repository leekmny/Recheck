# Recheck 작업 상태와 남은 범위

2026-11-16 점검 기준입니다. 구현한 기능, 실제 도구로 확인한 범위, 실행 파일 검증과 공개 이력을 구분합니다. 후속 결과는 공개 시작 이후의 정확한 커밋과 Actions·PR에서 확인하세요.

## 소스 공개와 기존 검증 기록

공개 원격은 [leekmny/Recheck](https://github.com/leekmny/Recheck)이며, 검토한 소스 스냅샷에서 새 Git 이력으로 시작합니다. 과거 작성자 정보와 연결된 개발 커밋·PR·Actions·태그는 별도 비공개 보관본에 유지합니다. [공개 이력 구성](PUBLIC_HISTORY.md)과 [공개 정책](PUBLICATION_SCOPE.md)을 따릅니다.

앱 소스의 기준 버전은 0.1.0입니다. 새 Windows 릴리즈 ZIP에 Recheck.exe와 실행용 Python·Qt를 포함하고 필요한 도구의 설치와 분석 환경 구성을 앱에서 돕습니다. 이전 실행 파일은 비공개 보관본에 유지합니다. 커밋·push만으로 사용자 EXE가 갱신되지는 않습니다.

도구 설치·관리는 PATH 밖의 기존 설치를 확인하며, Git/Python은 소스 개발용 선택 도구로 구분합니다. 설치가 필요한 도구는 고정 공식 WinGet 패키지 또는 공식 다운로드를 안내합니다. Docker 소스 빌드는 명시적 준비 버튼에서만 실행하고 소스 해시·플랫폼·불변 이미지 ID를 확인하여 로컬 영수증으로 저장합니다. 공개 ZIP에는 과거 비공개 Docker TAR·인증·모델을 포함하지 않습니다. [처음 실행](FIRST_RUN.md)을 참고하세요.

새 Windows 환경의 긴 경로 실패를 반영하여 실행·정적 분석의 파일 작업을 보완했습니다. Python 파일 입출력과 Docker·배치 실행의 경로를 구분하며 시스템의 긴 경로 정책을 변경하지 않습니다. 로컬 확장 경로를 네트워크 UNC로 오인하던 설치 탐색과 접근성 목록 선택 시 화면 전환도 수정했습니다. 실제 UNC·장치 경로 제한은 유지합니다. 임의로 긴 배치 설치 경로는 짧은 경로 사용을 안내하며 모든 외부 도구의 긴 경로 지원을 보장하지는 않습니다.

아래 실제 도구·EXE·정확도 수치는 공개 이전의 기능 검증 기록입니다. 비공개 보관본의 과거 결과를 새로운 공개 CI의 성공이나 새 실행 파일의 검증으로 계산하지 않습니다. 공개 커밋의 자동 검사는 새 저장소의 Actions 결과가 기준입니다. GitHub 로그인과 앱의 AI 로그인은 별개이며 사용자별 인증 자료는 공개 소스에 포함하지 않습니다.

## 후보 소스에서 진행한 작업

- 쉬운 입력의 편집 내용을 비교·내보내기·다른 입력 선택 전에 반영합니다. 잘못된 따옴표가 있으면 이전 값으로 실행하는 대신 수정을 요청합니다.
- 정적 분석 허용과 실제 실행 허용을 분리했습니다. 자동 비교는 정적 분석을 기본으로 수행하고 실행 미지원 대상도 정적 근거·보고서를 남깁니다.
- 네이티브 ELF·PE·단일 아키텍처 Mach-O는 REA/Ghidra, .NET PE는 REA 관리 메서드 경로를 사용합니다. 관리 코드는 메서드·시그니처·CIL·예외 메타데이터로 비교하며 C# 복원이나 실행 관측으로 표시하지 않습니다.
- worker 중단 시 한국어 재시도 안내와 원시 오류를 보존합니다. 정확도 측정기는 메모리 반환과 디스크 snapshot을 따로 기록해 저장 실패를 드러냅니다.
- Docker 안의 Windows VM 경로를 조사하고 진단 스크립트·설치 시험용 compose 초안을 추가했습니다. 제품 실행 backend에는 연결하지 않았습니다.

## REA 기능과 제품 비교 경로

요구사항은 **REA가 지원하는 프로그램에 대한 비교를 기본 기능에 포함하는 것**입니다. 후보의 네이티브·관리 코드 경로는 그 일부를 구현합니다. REA 도구의 존재, 제품 입력 허용, 실제 비교 검증은 각각 다릅니다. 아래 미구현 항목이 남아 있으므로 전체 요구사항 완료로 표시하지 않습니다.

| 대상 | REA 분석 경로 | 후보 Recheck의 기본 비교 | 실제 확인과 제한 |
| --- | --- | --- | --- |
| ELF x86-64 콘솔·PIE | 네이티브 함수·디컴파일·CFG | 정적·고정 Linux 환경 실행 비교 | 자체 샘플의 기존 실행 검증 유지. 등록 입력 범위 |
| PE x64 네이티브 콘솔·DLL | 네이티브 함수·디컴파일·CFG | 기본 정적 비교 | 콘솔은 기존 실제 비교, 후보 DLL은 양쪽 44함수 확인. 부족한 관계·facet은 partial. Windows 실행 미지원 |
| PE GUI·x86·ARMNT·ARM64, ELF32·ARM·공유 라이브러리 | 해당 형식을 처리하는 네이티브 provider | 헤더에 따라 정적 경로 허용 | 헤더·라우팅 검사이며 모든 형식·아키텍처의 실제 도구 검증은 아님 |
| 단일 아키텍처 Mach-O | 네이티브 분석 | 기본 정적 비교 | 자체 x64·ARM64 샘플에서 각각 1함수 변경 확인. fat/universal·macOS 실행 미지원 |
| .NET PE/CLI | 관리 artifact·메서드 조사 | 기본 메서드·시그니처·CIL 비교 | 자체 DLL 두 파일의 2메서드 대응과 Add의 CIL 변경 확인. CLR 실행·C# 복원 없음 |
| ASAR·JavaScript·Electron 패키지 | 애플리케이션 그래프·버전 비교 | 미구현 | 그래프·모듈·export 차이의 제품 스키마·보고서 연결 필요 |
| Android APK | 패키지·클래스·메서드·참조 조사 | 미구현 | JADX/Java 조건과 전용 근거·대응 규칙 필요 |
| ZIP·IPA·MSIX·AppX·DMG 등 패키지 | artifact inventory·구성원 비교 | 미구현 | inventory 차이와 프로그램 동작 차이를 구분할 계약 필요 |
| 브라우저·Electron 실행 상태 | bundle·CDP/Inspector·시나리오 관측 | 미구현 | 지정 대상·입력·동작과 실행 수명·결과 비교 계약 필요 |
| WebAssembly | WASM 구조·WAT 조사 | 미구현 | WABT 조건·함수 대응·glue 범위 필요. WAT는 원본 소스가 아님 |
| 펌웨어 | 영역 조사·명시적 추출·구성원 분석 | 미구현 | Binwalk/Unblob 등 provider 조건과 추출·비교 경계 필요 |
| PCAP·HAR·SAZ 등 기록 | 패킷·네트워크 기록 조사 | 미구현 | 기록의 범위·순서·손실과 비교 기준 필요. 라이브 캡처와 구분 |
| 기타 전용 metadata·기록 | Go/Rust metadata, EVM, DB·신호 기록 등 | 미구현 | 개별 도구의 입력·provider·근거 범위와 별도 비교 계약 필요 |

REA 경로는 도구 설명에 따른 범위이며 모든 provider가 동봉 이미지에서 준비됐다는 뜻은 아닙니다. 고정한 REA 버전과 외부 도구의 실제 가용성도 형식별로 검증해야 합니다. 허용 조건은 `recheck/models.py`, worker 경로는 `resources/docker/static/worker.mjs`와 `managed.mjs`, 근거 비교는 `recheck/comparison.py`에 있습니다. 세부 제한은 [지원 매트릭스](DISTRIBUTION_AND_RECOVERY.md#파일-지원-매트릭스)를 따릅니다.

자동 검사 수는 문서 작성 시점의 기록입니다. 후속 수정 후에는 전체 검사를 새로 수행하고 해당 커밋의 결과를 남깁니다. 기존 버전의 통과 수를 재사용하지 않습니다. 자세한 과거 결과는 [검증 범위 기록](검증범위.txt)을 참고하세요.

비공개 보관본의 1.2.1 프로토타입 EXE SHA-256은 `98c9e023eaae01f43d43231c8f6631a1a9eab340eb5e1646d4a137351a48cc3f`, 당시 embedded source identity는 `9b018f1c6efb02157eca71ecbfa4caf9f3d7b503f1522f0712b5c9d193208b29`입니다. 이 값은 현재 공개 소스의 identity나 공개 다운로드를 뜻하지 않습니다. 문자열·통계·파일 입력의 이전 후속 평가 기록도 확인했습니다. GPT 설명은 3/3 정답 근거와 대조됐으며 로컬 모델은 각각 300.414/300.519/300.475초 타임아웃입니다. 기존 산술·분기·반복 평가와 별도 기록이고 이번 공개 구성에서 AI를 재호출한 결과가 아닙니다. 짧은 CPU readiness 응답과 설명 성공을 혼동하지 않습니다.

## 다음 작업

1. **공개 소스에서 새 검증·배포를 진행합니다.** 공개 이력의 정확한 SHA와 CI를 확인합니다. 실행 파일은 외부 구성요소의 재배포 자료 검토 → 최종 검사·입력 불변 확인 → source identity → 새 staging → 실제 frozen EXE·GUI·고정 정답 → ZIP inventory 대조를 거쳐 새 공개 태그·릴리즈로 게시합니다. 이전 비공개 태그·첨부·백업은 별도 보관하며 공개 이력으로 가져오지 않습니다.
2. **REA 형식별 비교를 확대합니다.** 미구현 행마다 입력 식별·provider·근거 스키마·양쪽 대응·GUI·보고서·불완전 범위를 연결합니다. 자체 원본·변형으로 실제 검증한 뒤 지원 표를 갱신합니다. 단순 확장자 허용으로 대체하지 않습니다.
3. **Windows 실행 worker를 구현합니다.** [Windows Docker 조사](WINDOWS_DOCKER.md)에 따라 실제 게스트를 준비하고 고정 원본 디스크·매 실행 overlay·동일 입력/자원·원시 출력·종료 코드·nonce/해시·timeout/취소·정리 계약을 구현합니다. Linux 컨테이너에 PE를 넣거나 호스트 실행으로 대체하지 않습니다. Windows 출력·개행 oracle도 따로 고정합니다.
4. **깨끗한 설치·GUI 재시작을 검증합니다.** 배포 ZIP 자체로 표준 사용자·한글/공백 경로·작은 화면에서 로그인→준비→입력→비교→보고서→재시작을 확인합니다. 호스트→WSL2→QEMU Windows→게스트 WSL2/Docker의 추가 중첩 단계는 실측이 필요하며 QEMU 게스트 Docker Desktop은 공식 지원 범위와 구분합니다.
5. **남은 장애·AI 평가를 보완합니다.** Windows 디스크/SQLite 부족, 앱·AI 실행 중 강제 종료의 미실행 조합, 설치 복사 중단·schema/역마이그레이션을 별도 시험합니다. 문자열·통계·파일 입출력의 AI 설명은 고정 정답·업무별 요청 예산으로 평가하고 최초 실패·재시도를 분리합니다. 짧은 로컬 응답을 기존 300초 설명 미응답의 해결로 표시하지 않습니다.

명령은 [배포·복구 안내](DISTRIBUTION_AND_RECOVERY.md), 원격 반영은 [GitHub 작업 안내](GITHUB_WORKFLOW.md)를 따릅니다. 개인 인증·분석 원본·VM 디스크·모델·원시 QA 자료는 Git에 올리지 않습니다.
