# Recheck 작업 상태와 남은 범위

2026-11-17 버전 정리 기준이며, 아래 과거 도구 검증 기록은 2026-11-16 점검 내용입니다. 구현한 기능, 실제 도구로 확인한 범위, 실행 파일 검증과 공개 이력을 구분합니다. 후속 결과는 공개 시작 이후의 정확한 커밋과 Actions·PR에서 확인하세요.

## 프로젝트 목적과 0.2.0의 범위

Recheck의 목표는 프로그램과 배포물을 비교하고 차이와 확인 범위를 재현할 수 있는 근거로 남기는 것입니다. 버전 간 회귀 검사, 교체 후보의 동작 확인, 언어 간 포팅 검증, 정적 구조 검토, 패키지 구성 비교에 적용합니다. 0.2.0에서는 여러 실행 방식의 시나리오를 같은 비교 흐름에서 검증할 수 있도록 확장했습니다.

별도 시나리오 스키마로 다중 플랫폼·런타임과 콘솔·HTTP·웹·데스크톱·라이브러리 관찰을 연결했습니다. Linux Docker 실측, 자체 Windows 예제 검증, 정적 추출과 릴리스 관문의 상태를 기록했습니다. 아래의 이전 작업 기록은 해당 날짜의 범위입니다. [업데이트와 지원 매트릭스](PORTING_VALIDATION_UPDATE.md)

## 캡스톤 피드백 재점검

2026-11-18의 캡스톤 범위는 **레거시를 대체할 새 구현을 사용자가 준비하고, 같은 입력의 실행 관찰과 정적 근거를 대조하는 검증 지원**입니다. [요구사항·근거·발표 안내](https://github.com/leekmny/Recheck/blob/v0.1.7/docs/CAPSTONE_FEEDBACK.md)에 기존 근거, 수정 사항, 실제 실험과 미측정 범위를 정리했습니다. 아래의 과거 검사 수·정확도 기록은 해당 시점의 실행 결과입니다.

정적 구조 점수는 함수 대응 후보를 찾는 휴리스틱이고, 동적 일치율은 유효하게 비교한 입력 쌍의 관찰입니다. 두 지표가 충돌해도 하나를 다른 하나의 정답으로 취급하지 않습니다. 자동 복제·복호화·저작권 침해 확률 또는 모든 입력의 동등성은 이 프로젝트의 검증 결론이 아닙니다. GUI의 다시 만들기·개선하기 및 CLI의 `reconstruct`·`modernize`는 현재 요청·원본을 보관한 뒤 미구현으로 차단되는 단계이며, 자동 소스 생성 기능을 제공한 것으로 계산하지 않습니다.

## 소스 공개와 기존 검증 기록

공개 원격은 [leekmny/Recheck](https://github.com/leekmny/Recheck)이며, 검토한 소스 스냅샷에서 새 Git 이력으로 시작합니다. 과거 작성자 정보와 연결된 개발 커밋·PR·Actions·태그는 별도 비공개 보관본에 유지합니다. [공개 이력 구성](PUBLIC_HISTORY.md)과 [공개 정책](PUBLICATION_SCOPE.md)을 따릅니다.

이 문서의 소스 버전은 **0.2.0 후보**입니다. 실행 ZIP과 버전별 게시 결과는 [릴리스 목록](https://github.com/leekmny/Recheck/releases)에서 확인하고, [0.1.6 기록](https://github.com/leekmny/Recheck/releases/tag/v0.1.6)은 이전 배포의 근거로 참고하세요. 소스 검사와 각 배포본의 실행 검증은 별개입니다. ZIP에는 Recheck.exe와 실행용 Python·Qt를 포함하며 필요한 도구의 설치와 분석 환경 구성을 앱에서 돕습니다. 초기 개발 단계의 버전 이름 변경은 [대응표](PUBLIC_HISTORY.md#공개-버전-이름-정리)에 남기고, 각 버전의 배포물은 새로 빌드·검증합니다. 과거 비공개 실행 파일과 역사적 식별자는 보관본에 유지합니다. 커밋·push만으로 사용자 EXE가 갱신되지는 않습니다.

도구 설치·관리는 PATH 밖의 기존 설치를 확인하며, Git/Python은 소스 개발용 선택 도구로 구분합니다. 설치가 필요한 도구는 고정 공식 WinGet 패키지 또는 공식 다운로드를 안내합니다. Docker 소스 빌드는 명시적 준비 버튼에서만 실행하고 소스 해시·플랫폼·불변 이미지 ID를 확인하여 로컬 영수증으로 저장합니다. 공개 ZIP에는 과거 비공개 Docker TAR·인증·모델을 포함하지 않습니다. [처음 실행](FIRST_RUN.md)을 참고하세요.

새 Windows 환경의 긴 경로 실패를 반영하여 실행·정적 분석의 파일 작업을 보완했습니다. Python 파일 입출력과 Docker·배치 실행의 경로를 구분하며 시스템의 긴 경로 정책을 변경하지 않습니다. 로컬 확장 경로를 네트워크 UNC로 오인하던 설치 탐색과 접근성 목록 선택 시 화면 전환도 수정했습니다. 실제 UNC·장치 경로 제한은 유지합니다. 임의로 긴 배치 설치 경로는 짧은 경로 사용을 안내하며 모든 외부 도구의 긴 경로 지원을 보장하지는 않습니다.

아래 과거 실제 도구·EXE·정확도 수치는 당시의 기능 검증 기록입니다. 비공개 보관본의 과거 결과를 새로운 공개 CI의 성공이나 새 실행 파일의 검증으로 계산하지 않습니다. 공개 커밋의 자동 검사는 새 저장소의 Actions 결과가 기준입니다. GitHub 로그인과 앱의 AI 로그인은 별개이며 사용자별 인증 자료는 공개 소스에 포함하지 않습니다.

## 0.1.6의 AI 연결 정리

추천 ChatGPT → Gemini 무료(API) → 공통 AI 계정 연결 순서로 안내하고, 로그인·키 발급은 외부 브라우저를 기본으로 합니다. 내장 표시 선택은 기본 해제이며 Google 인증 제한은 안내와 이동 차단으로 유지합니다. 연결된 제공자는 새 로그인 대신 읽기 전용 상태 확인과 연결 해제를 제공하고, 비교 화면에서는 준비된 AI 하나를 선택합니다. 여러 AI의 자동 병렬 비교는 이번 범위에서 제외했습니다.

정상 앱 데이터에서 ChatGPT 인증·권한·기본 응답·JSON·보호된 검사 기록을 확인했으며 도구 호출 검사는 통과하지 않았습니다. 최종 변경의 전체 검사·새 실행 파일·게시 여부는 [작업 기록](https://github.com/leekmny/Recheck/blob/main/docs/decisions/2026-11-17-embedded-login-work-log.md)과 [인증 상태](AI_AUTH_STATUS.md)를 따릅니다. 과거 빌드 통과나 사용자 연결 보고만으로 최종 배포 완료를 표시하지 않습니다.

## 0.1.3의 확인 범위·재검사·실패 보고서

실제 보관 근거로 함수 목록·의사코드·제어 흐름·명령·호출·CIL 및 실행 입력의 수집 범위를 나누어 표시합니다. 불명확한 분모는 추정하지 않고 원래 성공 기록을 전체 근거 수집 성공으로 바꾸지 않습니다. 유효 원시 관찰로 화면과 보고서의 동적 지표를 검증하며 저장한 비교 정책과 입력 재현 여부를 확인합니다.

발견한 불일치·미측정 입력을 보관하고 새 동적/AI끔 분석으로 재검사합니다. 원본 결과와 묶음은 보존하며 기준 파일 변경·차이 유지·현재 쌍 일치·미측정을 구분합니다. 별도 실패 HTML/JSON은 원인·다음 조치·미관측 함수 ID를 모으고, 명시한 경우만 제한된 입력·출력 원문을 포함합니다. [상세 사용법](REVIEW_AND_RECHECK.md)을 참고하세요.

점검 R01 재해석 요청 상태와 기존 분석 상태 분리, R06 이력의 선택 행 우선, R03 손상 관찰 제외, R04 안전한 준비 원인·조치 전달을 보완했습니다. R02는 수집 범위 표시를 개선한 단계이며 함수별 추가 디컴파일·피연산자 근거 확장은 후속입니다. 프로그램 실행 동등성 전체나 깨끗한 다른 PC 설치를 증명하지 않습니다.

## 0.1.2에서 추가한 분석 모드와 설치 안내

정적분석·동적분석·둘 다 분석을 선택하고 AI 설명을 별도로 켜거나 끕니다. 기본은 둘 다 분석입니다. 시작 전에 선택한 분석의 도구와 파일 지원 범위를 확인하며, 부족한 도구는 설치·관리 화면으로 연결합니다. 지원하지 않는 파일에 도구 설치만으로 실행 가능하다고 안내하지 않고, 다른 모드로 자동 변경하거나 호스트에서 대신 실행하지 않습니다. 결과와 HTML 보고서는 정적·동적·AI 상태를 따로 표시합니다. [분석 모드 안내](ANALYSIS_MODES.md)를 참고하세요.

0.1.2는 분석 범위와 도구 안내를 개선한 버전입니다. 위의 0.1.3 보완과 구분하며 모든 함수의 추가 추출·모든 형식의 동적 실행을 제공한 것은 아닙니다.

## 0.1.1에서 추가한 연결과 비교 범위

- **새 설치는 Gemini 무료, 추천 AI는 GPT**로 안내합니다. Gemini 3.5 Flash-Lite를 사용하며 자신의 키 저장·실제 응답·JSON·보호된 검사 결과 저장 전에는 연결이 활성화되지 않습니다. 기존 프로필·선택·예산은 보존하고 유료 모델로 자동 전환하지 않습니다. [Gemini 무료 설정](GEMINI_FREE_SETUP.md)을 따릅니다.
- 실제 사용자 키로 Flash-Lite의 기본 응답·JSON·도구 호출 왕복·검사 결과 저장을 확인했습니다. 고정3입력의2일치/1차이에서 입력100에 대한900/1000 출력 차이를 설명과 대조했습니다. 최초 JSON 코드 울타리 응답은 거절하고 업무 예산 내 수정 응답을 검증했습니다. 실제 지표는 AI가 변경하지 않았습니다.
- Hydrogen의 최초 작은 기능검사는 긴 nonce 응답이256토큰에서 길이 초과하여 실패했습니다. 이를 숨기지 않고 기본 모델에서 제외했으며, Flash-Lite의 별도 성공과 구분합니다. 무료 프로젝트 등급은 사용자가 확인했으며 API성공만으로 독립 증명한 것은 아닙니다. 모든 모델의 설명 정확도나 깨끗한 다른 PC 성공을 뜻하지 않습니다. [AI 검증 상태](AI_AUTH_STATUS.md)를 참고하세요.
- **ZIP·패키지 구성 비교**를 GUI와 `compare-package` CLI에 추가했습니다. AI·Docker·파일 추출·실행 없이 추가·삭제·변경·유지를 표시하고 JSON/HTML로 내보냅니다. STORED/DEFLATE와 정해진 상한만 지원하며 손상·미지원·부분 수집은 같다고 계산하지 않습니다. [상세 범위](PACKAGE_COMPARISON.md)는 코드 의미·앱 유효성·서명 검증과 별개입니다.

이 절은 실제 계정 시험과 소스 기능 범위의 기록입니다. 새 릴리스의 최종 전체 검사 수·CI·EXE·ZIP 해시는 해당 버전의 공개 릴리스와 Actions에서 따로 확인합니다.

## 후보 소스에서 진행한 작업

- 쉬운 입력의 편집 내용을 비교·내보내기·다른 입력 선택 전에 반영합니다. 잘못된 따옴표가 있으면 이전 값으로 실행하는 대신 수정을 요청합니다.
- 정적 분석 허용과 실제 실행 허용을 분리했습니다. 자동 비교는 정적 분석을 기본으로 수행하고 실행 미지원 대상도 정적 근거·보고서를 남깁니다.
- 네이티브 ELF·PE·단일 아키텍처 Mach-O는 REA/Ghidra, .NET PE는 REA 관리 메서드 경로를 사용합니다. 관리 코드는 메서드·시그니처·CIL·예외 메타데이터로 비교하며 C# 복원이나 실행 관측으로 표시하지 않습니다.
- worker 중단 시 한국어 재시도 안내와 원시 오류를 보존합니다. 정확도 측정기는 메모리 반환과 디스크 snapshot을 따로 기록해 저장 실패를 드러냅니다.
- Docker 안의 Windows VM 경로를 조사하고 진단 스크립트·설치 시험용 compose 초안을 추가했습니다. 제품 실행 backend에는 연결하지 않았습니다.

## REA 기능과 제품 비교 경로

요구사항은 **REA가 지원하는 프로그램에 대한 비교를 기본 기능에 포함하는 것**입니다. 후보의 네이티브·관리 코드 경로는 그 일부를 구현합니다. REA 도구의 존재, 제품 입력 허용, 실제 비교 검증은 각각 다릅니다. 아래 미구현 항목이 남아 있으므로 전체 요구사항 완료로 표시하지 않습니다.

REA 경로는 도구 설명에 따른 범위이며 모든 provider가 동봉 이미지에서 준비됐다는 뜻은 아닙니다. 고정한 REA 버전과 외부 도구의 실제 가용성도 형식별로 검증해야 합니다. 허용 조건은 `recheck/models.py`, worker 경로는 `resources/docker/static/worker.mjs`와 `managed.mjs`, 근거 비교는 `recheck/comparison.py`에 있습니다. 세부 제한은 [지원 매트릭스](DISTRIBUTION_AND_RECOVERY.md#파일-지원-매트릭스)를 따릅니다.

GPT 설명은 3/3 정답 근거와 대조됐으며 로컬 모델은 각각 300.414/300.519/300.475초 타임아웃입니다. 기존 산술·분기·반복 평가와 별도 기록이고 이번 공개 구성에서 AI를 재호출한 결과가 아닙니다. 짧은 CPU readiness 응답과 설명 성공을 혼동하지 않습니다.

## 다음 작업

1. **공개 소스에서 새 검증·배포를 진행합니다.** 공개 이력의 정확한 SHA와 CI를 확인합니다. 실행 파일은 외부 구성요소의 재배포 자료 검토 → 최종 검사·입력 불변 확인 → source identity → 새 staging → 실제 frozen EXE·GUI·고정 정답 → ZIP inventory 대조를 거쳐 새 공개 태그·릴리즈로 게시합니다. 이전 비공개 태그·첨부·백업은 별도 보관하며 공개 이력으로 가져오지 않습니다.
2. **REA 형식별 비교를 확대합니다.** 미구현 행마다 입력 식별·provider·근거 스키마·양쪽 대응·GUI·보고서·불완전 범위를 연결합니다. 자체 원본·변형으로 실제 검증한 뒤 지원 표를 갱신합니다. 단순 확장자 허용으로 대체하지 않습니다.
3. **Windows 실행 worker를 구현합니다.** [Windows Docker 조사](WINDOWS_DOCKER.md)에 따라 실제 게스트를 준비하고 고정 원본 디스크·매 실행 overlay·동일 입력/자원·원시 출력·종료 코드·nonce/해시·timeout/취소·정리 계약을 구현합니다. Linux 컨테이너에 PE를 넣거나 호스트 실행으로 대체하지 않습니다. Windows 출력·개행 oracle도 따로 고정합니다.
4. **깨끗한 설치·GUI 재시작을 검증합니다.** 배포 ZIP 자체로 표준 사용자·한글/공백 경로·작은 화면에서 로그인→준비→입력→비교→보고서→재시작을 확인합니다. 호스트→WSL2→QEMU Windows→게스트 WSL2/Docker의 추가 중첩 단계는 실측이 필요하며 QEMU 게스트 Docker Desktop은 공식 지원 범위와 구분합니다.
5. **남은 장애·AI 평가를 보완합니다.** Windows 디스크/SQLite 부족, 앱·AI 실행 중 강제 종료의 미실행 조합, 설치 복사 중단·schema/역마이그레이션을 별도 시험합니다. 문자열·통계·파일 입출력의 AI 설명은 고정 정답·업무별 요청 예산으로 평가하고 최초 실패·재시도를 분리합니다. 짧은 로컬 응답을 기존 300초 설명 미응답의 해결로 표시하지 않습니다.
