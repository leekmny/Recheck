# 공개 이력의 시작점과 보존 범위

이 공개 저장소는 검토한 현재 소스 스냅샷을 시작점으로 새 Git 이력을 구성합니다.
기존 작성자 식별 정보가 들어 있는 과거 커밋뿐 아니라 연결된 PR·Actions 기록도
공개 저장소와 분리하기 위한 방식입니다. 원래 이력에 `.mailmap`을 추가하는
것만으로 과거 Git 데이터가 지워졌다고 주장하지 않습니다.

## 두 저장소의 역할

| 구분 | 내용 |
| --- | --- |
| 공개 `leekmny/Recheck` | 검토한 소스·테스트·자체 샘플·선별 문서와 공개 시작 이후의 이력 |
| 별도 비공개 보관 저장소 | 원래 개발 커밋·PR·Actions·태그·실행 파일과 그 검증 기록 |

두 저장소는 서로 다른 Git 이력을 가집니다. 이전 커밋·PR 번호·Actions 실행
번호·태그가 이 공개 저장소에서 같은 대상으로 조회된다고 가정하지 않습니다.
예전 링크를 새 공개 저장소의 주소로 바꿔서 과거 검증 기록인 것처럼 표시하지
않습니다. 공개 문서의 과거 수치는 수행 당시의 검증 범위를 요약한 것이며
현재 공개 커밋의 CI 성공이나 새 실행 파일 검증으로 계산하지 않습니다.

앱의 기준 소스 버전은 1.2.1-prototype.1입니다. 공개 이력 시작은 새 제품 기능이나
새 EXE 배포가 아닙니다. 과거 EXE의 원본 소스는 비공개 보관본의 해당 태그와
embedded source identity가 기준입니다. 라이선스·고지·소스 제공 자료를 검토한
새 실행 파일을 별도 검증하기 전까지 공개 다운로드를 제공하지 않습니다.

## 이후 개발 시 지킬 규칙

1. 새 공개 저장소를 clone하고 origin이 정확히 `leekmny/Recheck`인지 확인합니다.
2. GitHub가 제공하는 자신의 noreply 주소를 author·committer에 사용하고,
   commit 전후 메타데이터와 변경 파일을 확인합니다.
3. 비공개 보관 clone의 origin은 별도 비공개 보관 원격을 가리켜야 합니다.
   해당 clone의 refs·태그·과거 커밋을 공개 원격으로 push하지 않습니다.
4. `git push --mirror`, 과거 `.git` 복원, 비공개 이력의 merge/cherry-pick으로
   과거 작성자 정보를 다시 가져오지 않습니다. 필요한 변경은 현재 공개 소스에서
   새로 작성하고 검토합니다.
5. PR·CI·릴리즈는 공개 시작 이후의 정확한 SHA와 새 태그를 기준으로 합니다.
   관리 명령에는 검토한 `--branch`와 `--tag`를 명시합니다.
6. 공개 로그·댓글·첨부에는 인증 정보·개인 분석 원본·로컬 QA를 넣지 않습니다.
   공개 범위와 제보 방법은 [PUBLICATION_SCOPE.md](PUBLICATION_SCOPE.md),
   [SECURITY.md](../SECURITY.md)를 따릅니다.

공개 시작 후의 결과는 공개 Actions와 이후 PR에서 확인합니다. 초기 공개 CI가
완료되기 전에 과거 비공개 CI를 새 공개 CI의 성공으로 표시하지 않습니다.

## 병합 시 작성자 이메일

GitHub의 서버 병합은 계정의 기본 이메일을 새 커밋에 넣을 수 있습니다.
따라서 관리 도구는 공개 저장소의 서버 병합 요청을 차단합니다. 웹 병합도
이메일 설정을 검토하기 전에는 사용하지 마세요. 필요한 병합은 검토한 PR
head를 로컬에서 자신의 noreply author·committer로 정상 merge하고, 그 merge
커밋을 별도 브랜치의 CI로 확인한 뒤 main에 반영합니다. 과거 비공개 refs나
태그는 이 과정에 사용하지 않습니다. noreply override가 서버에서 거부됐다고
개인 이메일을 기본값으로 두고 자동 재시도하지 않습니다.


## 초기 개발 버전 번호 안내

연구·초기 개발 단계를 명확히 표시하기 위해 버전 체계를 0.x로 조정했습니다.
공개 이력의 대응은 1.2.2-prototype.1 → 0.1.0, 1.2.3-prototype.1 → 0.1.1,
1.2.4-prototype.1 → 0.1.2, 1.2.5-prototype.1 → 0.1.3입니다.
각 0.x 배포물은 대응하는 공개 소스에서 버전과 안내 문서를 수정하여 다시 빌드한 것으로,
기존 EXE나 ZIP의 해시를 그대로 사용하지 않습니다. 이전 공개 소스 커밋은 보존합니다.
그 이전 비공개 검증 기록의 버전·해시는 당시 원래 표기이며 새 공개 배포물의 식별자가 아닙니다.
