# 확인 범위·문제 입력 재검사·실패 보고서

Recheck 0.1.3는 분석을 어디까지 확인했는지 보여 주고, 발견한 동작 차이와 미측정 입력을 보관해 새 비교로 다시 검사합니다. 정적분석·동적분석·둘 다 분석 및 AI 별도 선택은 [분석 모드 안내](ANALYSIS_MODES.md)를 참고하세요.

## 실제로 확인한 범위

결과 상단의 수집 요약과 **확인 범위** 탭에서 다음 내용을 확인합니다.

- 함수·메서드 목록: 보관된 수, 확인 가능한 전체 수, 목록 수집 완료 여부
- 의사코드·제어 흐름·어셈블리·호출 관계·.NET CIL: 관측·완전 수집·일부 수집·미선택·실패·미관측·불명·대상 아님
- 입력: 등록·실측·미측정·미실행 수와 손상된 관찰, 중복·미등록 관찰
- 외부 함수와 본문 없는 메서드는 해당 본문 분석의 누락 분모에서 제외

예를 들어 함수130개 중 의사코드100개를 수집했다면 **100/130, 미선택30**을 표시합니다. 원래 기록이 성공이어도 이 수치는 전체 의사코드 수집 성공으로 바뀌지 않습니다. 일부 의사코드가 잘렸다면 관측은 했지만 완전 수집은 아닙니다. 전체 분모가 확인되지 않으면 `?`로 표시합니다.

원시 관찰의 Base64·출력 필드·종료 코드·상태를 다시 확인합니다. 손상된 관찰을 빈 출력이나 정상 일치로 계산하지 않습니다. 이전 기록에 비교 정책이 없으면 일치 여부를 추정하지 않습니다. 원래 저장된 결과와 원시 근거를 수정하지 않고 화면과 보고서에서 검증 가능한 범위를 표시합니다.

함수별 추가 디컴파일은 후속 범위입니다. 이 버전은 수집 범위의 표시를 개선하며 기존 추출 한도를 자동으로 늘리지 않습니다.

## 발견한 문제를 다시 검사하기

1. 비교 결과에서 **문제 입력 저장**을 누릅니다. 불일치·미측정·미실행 입력을 원래 기록에서 확인하여 새 입력 묶음으로 저장합니다. 정적분석의 함수 목록을 동적 회귀 테스트로 저장하지 않습니다.
2. **재검사 보관함**에서 묶음을 선택하고 **선택한 입력으로 재검사 준비**를 누릅니다. 지난 분석 화면에서도 보관함을 열 수 있습니다.
3. 저장한 입력·시간 제한·환경·출력 비교 정책을 사용합니다. 화면에서 원본과 수정본 파일을 확인하거나 다시 선택합니다. 입력과 정책을 수정하려면 **일반 비교로 전환**을 사용하세요.
4. 시작하면 동적분석·AI 끔으로 새로운 분석을 만듭니다. 기존 결과와 저장 묶음은 덮어쓰지 않습니다. 개인 AI·정규화 설정도 자동으로 바꾸지 않습니다.
5. 결과의 확인 범위에서 입력별 **이번 비교에서 일치·차이 유지·미측정**을 확인합니다.

‘이번 비교에서 일치’는 지금 선택한 두 파일이 저장 입력에서 같은 결과를 보였다는 뜻입니다. 과거 원본의 모든 동작 보존이나 결함 수정 전체를 증명하지 않습니다. 원본 파일의 해시가 저장 당시와 달라졌다면 별도 경고를 표시합니다.

보조 파일이 있으면 당시 관찰의 SHA-256과 일치하는 보관 바이트를 저장합니다. 바뀐 현재 파일을 과거 입력으로 대신 사용하지 않습니다. 저장한 보조 파일이 변경·누락되면 준비를 막고 원본을 보존합니다. 실제 새 실행에서 저장한 보조 파일을 재현했는지 확인할 수 없으면 재검사 결과는 미측정입니다.

입력 묶음은 이 PC의 Recheck 데이터 폴더에 저장합니다. 입력·환경 변수·보조 파일에 민감한 자료가 있을 수 있으므로 개인 분석 데이터로 관리하세요. 배포 ZIP에는 포함하지 않습니다.

## 실패 항목만 따로 내보내기

결과의 **실패 항목 보고서** 버튼 또는 **실패 항목** 탭에서 확인합니다.

| 분류 | 의미 |
| --- | --- |
| 동작 불일치 | 유효한 양쪽 관찰에서 출력·표준오류·종료 코드가 다름 |
| 실행 실패·미측정 | 시간 초과·취소·OOM·출력 잘림·손상·입력 재현 실패 등으로 유효 비교 불가 |
| 정적 근거 수집 미완료 | 관측하지 못한 함수·관계·본문과 불명확한 수집 범위 |
| 분석 단계 미완료 | 선택한 단계의 도구·파일·환경 문제 |
| AI 설명·요청 실패 | 실제 분석 상태와 분리되는 AI 연결·응답·문맥·취소 문제 |

보고서는 원인 코드·다음 조치·관측 범위와 미관측 함수 ID를 모읍니다. **HTML**은 읽고 공유하기 쉽게, **JSON**은 항목별 도구 분석에 사용합니다. 이미 있는 파일은 덮어쓰지 않으므로 새 이름을 지정하세요. 두 프로그램이 같은 유효한 비정상 종료 코드를 반환했다는 이유만으로 불일치나 실행 실패로 분류하지 않습니다.

기본 보고서는 입력·출력 원문·전체 경로·원문 로그·인증·전체 설정을 제외합니다. **재현용 입력·출력 원문 포함**을 선택하면 문제 입력, 제한된 길이의 stdout/stderr 및 원시 바이트 표현, 종료 코드와 일부 함수 이름을 포함합니다. 이 내용에 민감 정보가 있을 수 있으므로 공유 전에 미리보기를 확인하세요. 일부 비밀 이름의 환경 변수는 가리고, 보조 파일 본문·실행 파일·AI 키는 보고서에 넣지 않습니다. 생략·잘림은 명시합니다.

HTML과 JSON 내보내기는 기존 근거를 정리하며 대상 프로그램이나 AI를 새로 실행하지 않습니다. 새로운 비교 결과를 선택하면 원문 포함 선택이 해제됩니다. 비교 결과가 없는 작업을 열면 이전 실패 보고서는 해제되어 잘못된 결과를 내보내지 않습니다.

## CLI

```powershell
python -m recheck --data-dir DATA regression-save RUN_ID --name "경계 입력"
python -m recheck --data-dir DATA regression-list
python -m recheck --data-dir DATA regression-run SUITE_ID --original reference.bin --reimplementation fixed.bin
python -m recheck --data-dir DATA failure-report RUN_ID --output failures.html --format html
python -m recheck --data-dir DATA failure-report RUN_ID --output failures.json --format json --include-observations
```

CLI 재검사는 저장 당시의 정규화 정책과 현재 설정이 같아야 합니다. GUI는 재검사 화면에서 안내한 저장 정책을 해당 실행에만 적용합니다. 기존 `--json-output`으로 명령 결과를 별도 새 JSON 파일에 저장할 수 있습니다.

AI 재해석은 기존 분석 상태와 추가 요청의 성공·실패를 분리합니다. 실패한 재해석 요청은 CLI에서 성공0으로 반환하지 않으며 기존 실측과 이전 AI 응답은 기록에 남습니다. Docker 준비 실패도 안전한 원인 코드와 다음 조치를 제공하며 존재하지 않는 보고서를 안내하지 않습니다.

현재 동적 재검사는 Linux x86-64 ELF 콘솔 프로그램용입니다. Windows PE 실행 worker나 모든 입력의 동등성 검증을 추가한 버전은 아닙니다. [지원·복구 안내](DISTRIBUTION_AND_RECOVERY.md)에서 형식별 범위를 확인하세요.
