# ADR-0008 · 포팅 비교의 입력과 이력

- 상태 · 수락
- 적용 범위 · 0.2.1의 포팅 시나리오 비교

## 배경과 기준

포팅 비교는 매 시나리오에서 원본 경로를 읽어 실행 번들을 만들었다. 구조 분석도 시나리오 실행이 끝난 후 원본 경로를 다시 읽었다. 첫 시나리오가 시작된 뒤 입력을 덮어쓰면 이후 동작 관찰과 구조 점수의 입력이 달라졌다. 관찰을 받을 때마다 전체 결과를 JSON과 DB에 쓰는 방식에서는 DB 커밋이 실패하더라도 먼저 쓴 JSON에서 성공 결과를 읽을 수 있었다.

시나리오가 실행에 사용한 입력의 SHA-256을 남기고 정적 분석에서 동일한 경로를 사용할 때 그 사본을 사용해야 한다. 중단된 실행은 양쪽 판정이 끝난 관찰과 마지막에 받은 한쪽 관찰을 보존해야 한다. 이전 결과와 CLI·보고서의 결과 형식도 계속 사용할 수 있어야 한다.

## 결정과 대안

- 실행에 쓰는 파일과 구조 분석에 쓰는 파일을 시작 시 임시 디스크에 개별 복사한다. 각 사본을 사용할 때마다 매니페스트 경로와 연결한다. 전후 해시만 대조하면 이미 실행된 시나리오를 되돌릴 수 없고, 각 번들을 메모리에 보관하면 시나리오 간에 중복 입력이 쌓인다. 디스크 사본은 파일 크기만큼 공간을 필요로 한다. 여러 파일의 동일 시점 스냅샷은 파일시스템 지원을 요구하므로 파일의 수정이나 빌드는 비교 전에 완료한다.
- 포팅 실행의 상태와 관찰을 SQLite에 기록하고 시나리오 단위의 변경만 추가한다. 조회할 때 저장된 순서대로 상태를 복원한다. 전체 JSON을 최종 한 번만 저장하면 실행 중 사라질 수 있는 관찰이 늘어난다. JSON과 DB를 함께 유지하는 방식은 두 저장소의 커밋을 조정하고 실패 후 불일치를 복구하는 비용이 따른다. JSON 사본이 필요한 경우 CLI의 내보내기를 사용한다.
- 이미 저장한 포팅 결과는 기존 경로에서 읽는다. 그 결과를 일괄 변환하는 방식은 버전 설치 시 사용자 데이터 수정과 변환 실패의 위험을 추가하므로 필요할 때 원래 형식으로 조회한다.

## 검증과 재검토

파일 덮어쓰기를 중간에 일으키는 시나리오, SQLite의 관찰 및 최종 상태 쓰기 실패, 이전 이력 조회를 `tests/test_porting_contract.py`에서 확인한다. 배포 검증에서 저장 결과와 CLI·보고서의 출력을 비교한다. [사용법 및 호환성](../PORTING_VALIDATION_UPDATE.md)

실행 크기 상한을 늘리거나 여러 실행의 이력을 한 번에 가져오는 기능을 추가하면 SQLite 조회 비용과 데이터 보관 정책을 함께 검토한다.
